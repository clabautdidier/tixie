# Project Tixie: Architectuur & Design Specificaties

Tixie is een modulaire ITSM-applicatie gebouwd voor educatieve doeleinden (Troubleshooting & Support). Dit document beschrijft de technische fundering en de gemaakte ontwerpbeslissingen.

---

## 1. Architectuurschema

De applicatie is opgebouwd als een gedistribueerd systeem binnen een Docker-ecosysteem.



---

## 2. Componenten Overzicht

| Component | Technologie | Rol & Verantwoordelijkheid |
| :--- | :--- | :--- |
| **Backend API** | Spring Boot (Java) | De "Modular Monolith" die alle business logica, security en data-validatie afhandelt. |
| **Database** | PostgreSQL | Relationele opslag voor gebruikers, assets, locaties en procesdata. |
| **Database Migratie** | Flyway | Versiebeheer van het database-schema voor consistente omgevingen. |
| **Bestandsopslag** | S3 (Spring Cloud AWS) | Abstracte opslag voor media en documenten (werkt met AWS of lokaal via MinIO). |
| **Frontend UI** | Vanilla JS & Bootstrap 5 | Single Page Application (SPA) zonder frameworks, gebruikmakend van Web Components. |
| **Web Server** | Nginx | Serveert de frontend portals en fungeert als reverse proxy naar de API. |
| **Authenticatie** | JWT (JSON Web Tokens) | Stateless authenticatie en autorisatie gebaseerd op rollen. |

---

## 3. Infrastructuur & Deployment (Docker)

De applicatie wordt uitgerold via **Docker Compose** en bestaat uit minimaal de volgende containers:

1.  **tixie-api**: De Spring Boot applicatie.
2.  **tixie-db**: De PostgreSQL database instance.
3.  **tixie-customer-portal**: Nginx container voor de eindgebruiker-interface.
4.  **tixie-admin-portal**: Nginx container voor de IT-beheerder-interface.
5.  **tixie-storage** (Optioneel): Een MinIO container voor lokale S3-simulatie.

---

## 4. Functionele Modules

De applicatie is ontworpen om de volgende ITIL-processen stapsgewijs te implementeren:

* **User Management:** Beheer van gebruikers, rollen (Admin/Tech/User) en permissies.
* **Application Configuration:** Centraal beheer van systeeminstellingen en SLA-definities.
* **Configuration Management (CMDB):** Beheer van locaties en Configuration Items (CI's).
* **Incident Management:** Registratie en afhandeling van operationele storingen.
* **Problem Management:** Root cause analyse van terugkerende incidenten.
* **Knowledge Management:** Database met FAQ's en bekende oplossingen.
* **Service Management:** Definiëren van de service catalogus.

---

## 5. Troubleshooting Invalshoeken voor Studenten

De gekozen architectuur biedt specifieke leerdoelen voor foutopsporing:
* **Netwerk:** Communicatiefouten tussen Nginx, de API en de Database binnen het Docker-netwerk.
* **Security:** Debuggen van verlopen of ongeldige JWT-tokens en CORS-configuraties.
* **Data:** Flyway migratie-conflicten oplossen bij schema-wijzigingen.
* **Integratie:** Verbindingsfouten met de S3-bucket of verkeerd geconfigureerde environment variables.
